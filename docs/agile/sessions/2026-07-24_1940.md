## 1. Domain go-live fix — buildographic.com

**Problem:** `https://www.buildographic.com/` hung indefinitely; apex and `app.buildographic.com` worked fine.

**Root cause:** `www` was a Namecheap URL-forward record, correctly targeting `https://buildographic.com/` — but Namecheap's free forwarding only works over plain HTTP, never HTTPS. Every browser defaults to HTTPS first, so it just hung on port 443.

**Fix:** Migrated DNS to Cloudflare (free plan):
- Nameservers switched at Namecheap to Cloudflare's (`eugene.ns.cloudflare.com`, `zainab.ns.cloudflare.com`)
- Recreated all records in Cloudflare: apex + `app` CNAMEs to Railway, plus the existing Resend/SES email records (SPF, DKIM, DMARC, MX) — all verified intact
- Added `www` as a proxied CNAME to apex + a **Redirect Rule** (`http.host eq "www.buildographic.com"` → `concat("https://buildographic.com", http.request.uri)`, 301) — Cloudflare's edge now handles the redirect before it ever reaches Railway, sidestepping Railway Hobby's 2-custom-domain cap
- Iterated the redirect rule from Static → Dynamic to fix a trailing `?` bug, then to properly preserve path + query string

**Verified:** apex/app/www all return correct responses over HTTPS; HTTP→HTTPS redirects with no loop.
