## 6. BL-27 — traced, reviewed, deliberately not built

**Mechanism confirmed:** `splitElementsForAiBackground` (`canvasState.ts:338`) keeps everything that isn't an AI background or a `composed-` element, then places the AI image *beneath* them at `minZIndex - 1`. The template's text survives on top of an image that is already a finished composition. Three prices, two headlines.

**Dinesh's rule is right and beat mine.** I proposed dropping only *unedited* placeholders; he pointed out that if the user has already typed ₹1.85 Cr and the AI image carries ₹1.9 Cr, keeping the edited layer reproduces the bug exactly. The discriminator is **background vs complete poster**, not touched vs untouched. Values get preserved separately; layers get discarded.

**The enabling fact nobody had spotted:** the server already decides this and throws it away.

```ts
// ai-orchestrator.service.ts:274 — a local variable, used and discarded
const useTextFree = typeof photoReference === 'string' && photoReference.length > 0;
```

Persist that on the generation record and carry it to the canvas element, and the rule becomes a branch on a fact instead of an inference from pixels. `isAiImport` cannot substitute — it is `true` on both paths.

**Four decisions still needed before any code:**

1. **Non-template elements** — a user's own text box or uploaded logo has no slot tag, so it survives and floats over the poster. Does "replace" mean the composition or only template-owned layers?
2. **Undo across two stores** — removing layers *and* writing values into the property store needs one undo covering both. The existing history push (US-AI-053 AC2) covers only the canvas.
3. **Warn at generate time, not apply time** — the A/B choice is actually made by whether a photo was attached. Warning at "Use This Design" is after the credit is spent.
4. **What is a text-free background with no user photo?** Still unanswered, and it gates whether option A can ever be the default.

**Bonus worth remembering:** `usePropertyStore` has three consumers and **none of them writes to the canvas**. The form feeds AI generation only. So "preserve the values separately" would start building the slot→field binding from the discard side — BL-27's fix is a down payment on the data model, not throwaway work.
