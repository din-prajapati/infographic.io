Editable Layers Flow

How “Edit elements” behaves after the rebuild — the placement choice, the five control states, and what gets deleted to make them honest.

The canvas states what it is. Nothing else gets a vote.

Why the control lies today

The pill reads “Editable layers active” over a design whose text is plainly baked in. The cause isn’t the canvas — it’s that isEditableMode ORs in renderMode, a session-global preference written from two unrelated places: the Flat/Editable toggle in AI Chat, and silently by the toolbar itself after any successful compose.

Once either fires, every canvas in that session claims to be editable — including a freshly opened template holding no AI content at all. The control reports a preference, not a state.

today

Three sources of truth disagree about one question:

  • sticky renderMode
  • a canvas-content heuristic
  • activeGenerationId

after

One value, derived from provenance on the elements:

  • composed- ids mean real extracted layers
  • isAiImport means an un-extracted raster
  • renderMode no longer participates

The flow, end to end

The branch that matters is what happens when a generation lands on a canvas that already holds a template. That’s now the user’s call, asked once per editor session.

Placement decision → control state

Both placement outcomes already exist in code — they are the two branches of loadAiVariationToCanvas, today selected by a heuristic. The change is to select by the user’s choice instead. That keeps US-AI-036 AC3 intact: “use as background” is AC3, promoted from silent default to a named option.

Control states

Five states, one derivation, no preference input. The quiet win is the first row: with a template on canvas and no AI raster, the control disappears — because the text a user would want to edit is the template’s, and that is already real, selectable text.

What actually changes

Most of the value is in the two deletions.

delete
renderMode === 'editable' || from the control’s state derivation — the sticky-state bug itself.
delete
setRenderMode('editable') as a side effect of composing — the source of the stickiness.
add
An explicit mode: 'replace' | 'behind' parameter on loadAiVariationToCanvas, replacing the hasDeliberateOrigin guess.
add
The placement dialog, plus session memory so further variations don’t re-prompt.
keep
Both canvas loaders, planVariationLoad, the compose API, caching and credit rules — all unchanged.
keep
renderMode itself, narrowed to one job: intent for the next generation in AI Chat.
