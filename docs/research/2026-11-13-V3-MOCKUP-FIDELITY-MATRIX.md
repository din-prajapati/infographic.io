# V3 Listing editor — mockup-to-runtime fidelity matrix

Date: 2026-11-13. Branch `codex/v3-listing-responsive-handoff`, base `5f19b3c`.
Reference: `Mockups/listing-workflow-v1/editor.html` (loads `editor.js/css` → `refinement.js/css` → `p1-core.js`, `p1-model.js`, `p1.js/css`), served at `http://127.0.0.1:5194/editor.html`.
Runtime: `http://localhost:5000/editor?editor=v3&designId=…` (this worktree's dev server). The API was mocked in Playwright with a Lake View Villa record that matches the mockup's `SAMPLE-101` facts (₹1.25 Cr, 3 beds / 2 baths / 1,850 sq ft, Arjun Shah, ASTER REALTY).

## How the evidence was produced

Claude in Chrome was not connected, so both pages were driven with the repository's Playwright Chromium at 1440×900 (desktop), with extra captures at 390×844 (phone) and in dark theme. The scripts and PNGs live in `.e2e-artifacts/mockup-fidelity/` (git-ignored; rerun `node mock.cjs|mock2.cjs|rt.cjs` from that folder to regenerate them).

`mock-*` = mockup, `rt-*` = runtime before restoration. Suffixes: `d` desktop light, `dk` desktop dark, `m` phone.

## Precedence decisions

- **Shell chrome from the earlier approved V3 stays**: logo, Projects, editable title, cloud status, canvas Undo/Redo, Preview, rail icons, the floating element toolbar, the canvas footer (Layers, Canvas settings, zoom) and the AI Assistant button. The listing mockup is a listing-focused simplification of that shell and does not remove these controls. Its listing-specific chrome is restored *into* that shell.
- **Mockup-only simulations are not reproduced**: fictional `SAMPLE-101` lookup, "Demo records", photo roles and ranking, template packs, "Workflow" catalogue, Show links overlay, Approve design, SVG download and browser-local saving. These are excluded either by explicit user direction or by story Out-of-Scope.
- **Test-visible names that differ only in wording are kept** where real tests assert them: `Save property` (mockup: Save changes), `Asking price` (mockup: Sale price), `Save Agent`/`Save Brand`, `Apply listing updates` (the mockup also uses this label once a Design exists, which is always the case at runtime), and `Linked field` as the select's accessible name.

## Resolution — 2026-11-13 (Claude Code, Opus)

Rows 1–17 were implemented in the files listed, under the reconciled T3 allowlists in US-EDIT-020/021/022/025/044 `TASKS.md`. After-state screenshots are in `.e2e-artifacts/mockup-fidelity/after/` (`rt-d-*` and `rt-dn-*` desktop light, `rt-p-*` pending light, `rt-pk-*`/`rt-fk-*` dark, `rt-m-*` 390px, `rt-fx-*`/`rt-pkx-*` export light/dark).

Deliberate remaining differences from the mockup:

- The Listing ID search covers the user's **saved** catalogue. There is no fictional provider lookup (US-EDIT-025 AC2). The mockup's sample feed is a simulation.
- The saved-results count reads `N properties` rather than `N of M properties`. Search is server-side, so M is not known without a second request.
- Earlier-approved V3 shell controls remain (row precedence above), so the header carries canvas Undo/Redo and Preview in addition to the mockup's four listing actions.
- No Show-links overlay, Approve step, SVG download, template-pack dialog or Workflow catalogue. These are mockup simulations or out-of-scope features.
- The More menu item stays `Export` (it opens the same review dialog). The phone layout is an adaptation: the mockup has no phone design.
- Pre-existing bug fixed in passing: two Windows-1252 `…` bytes in `V3Editor.tsx` rendered as `Exporting�` and `Saving template�` in the More menu.
